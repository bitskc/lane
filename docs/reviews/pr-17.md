### Default button `checkable` + `checked` binding

**[Should-fix] (confidence: 9/10) `TargetsPage.qml:137-143` and `:220-226`**

```qml
checkable: true
checked: model.targetId === controller.defaultTargetId
onClicked: controller.defaultTargetId = model.targetId
```

Qt Quick Controls 2 breaks a `checked:` property binding on the first user
toggle. Clicking the row that is already default toggles `checked` to `false`
while `onClicked` re-assigns the same `defaultTargetId`; the button can stay
visually unchecked even though it remains the default. Clicking a different row
works on first selection; the Fallback combo (`TargetsPage.qml:512-517`) still
shows the real default.

**Recommended fix:** drop `checkable` and use `highlighted:` (or a read-only
indicator) driven by the binding, or wrap with `Binding { restoreMode:
Binding.RestoreBinding }`. Do not rely on plain `checked:` with `checkable:
true`.

Only browser and container delegates got Default buttons; PWA/custom/private
sections unchanged (matches prior scope).
