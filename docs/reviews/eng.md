# Lane engineering review, macOS port round

Scope: `git diff 8ba3be2..HEAD` (44 commits), the macOS port and every line of Linux code it touched.
Lens: architecture, correctness, failure modes, tests.
Verification: source read locally; macOS 26.6.1 machine probed read-only (ctest 20/20 pass, `lsregister -dump`, `com.apple.launchservices.secure.plist`, installed `Info.plist`).

## Verdict

**SHIP-BLOCKING CORRECTNESS DEFECT + ONE CONCURRENCY HOLE.** The port's seams are clean and the Linux refactor is faithful, but `makeDefaultHandler`'s content-type claims put Lane's bundle id on file-type roles the router cannot serve: on the port machine Lane is now the preferred opener for `public.html`, `public.xhtml`, and `com.apple.application-bundle`, while `UrlEventFilter` silently drops every `file://` URL it receives. A user who double-clicks an HTML file after making Lane the default gets nothing.

## Considered and fine

- `registerActivation` returning true unconditionally (platform_macos.mm:375-383): wiring exists and is real. `UrlEventFilter` is installed on `QApplication` at main.cpp:87-88, before `Controller` exists; cold-start `QFileOpenEvent`s queue in the bounded FIFO and drain through `setSink` at main.cpp:187 after positional argv is handled, so an explicit argv URL wins first (main.cpp:182). Second-instance `open -b` on a running daemon is delivered by LaunchServices to the live process, never spawning a second instance. The `openUrl` argument to `registerActivation` is dead on macOS (deliveries come via the filter), which is consistent with the header comment; a doc-only nit.
- `m_changeDeclined` set-once suspicion: false. `store(!ok)` at platform_macos.mm:357 clears it on success. The residual problems are covered by finding 3.
- SingleInstance on macOS: `confstr(_CS_DARWIN_USER_TEMP_DIR)` path at SingleInstance.cpp:150-165 yields `/var/folders/.../T/lane-<uid>.sock`, well under 103 bytes on stock macOS; fail-fast with no fallback is the right call (binding elsewhere = two primaries). Stale-socket handling is sound: ENOTSOCK/stale-regular-file reclaim via `stat` + `S_ISSOCK` (lines 88-90), two-phase probe-then-lock-then-reprobe ordering prevents the unlinked-inode race, and `QLockFile` stale detection (dead-PID check, not the disabled age timer) recovers a lock orphaned by `_Exit`/crash. `forwardToPrimary` releases the claim lock before writing the frame (line 94), matching the "hold the lock only for connect/remove/bind" comment.
- NotificationActionMap: mutex covers every mutation/read; `take()` extracts under lock and runs the action outside it (no lock-held user code, no deadlock); LRU eviction is bounded at 32 with a counter; actionless `add` returns empty. The lifetime question (delegate callback arriving after notify returned) is handled because the map is a static singleton. The remaining risk is the callback queue, which is finding 2.
- UrlEventFilter FIFO semantics: cap at 8 drops the newcomer, not the earliest click (verified by test_urlevents.cpp `queueIsBoundedAtEight`), drop is counted (`m_dropped`), non-http(s) is logged not queued, drain order is FIFO. `eventFilter` consuming non-web `FileOpen` events is correct (the default path only logs). The off-by-one in the diagnostic line is finding 6.
- Controller default-handler plumbing on macOS: `watchesDefaultHandlerByFile() == false` takes the `m_defaultPoll` 60 s QTimer branch (Controller.cpp:125-131), `setWatchdogEnabled` toggles it symmetrically with `m_defaultWatcher` (lines 370-375), and `makeDefaultBrowser`'s callback refreshes state and emits `defaultBrowserChanged` (lines 755-760), so the "status only updates on emit" worry is handled: every state transition path calls `refreshDefaultBrowserState` then emits.
- CMake: `lane-app` static lib carries shared app sources; `laneuiplugin` is linked into `lane` on macOS the same way as Linux (src/CMakeLists.txt:163); `MACOSX_BUNDLE_INFO_PLIST` `${LANE_VERSION_STRING}` resolves because the non-ECM fallback sets the variable at CMakeLists.txt:86 and CMake substitutes `${VAR}` in plist templates (verified: built Info.plist has CFBundleVersion 0.3.0). ObjC++ enabled only on APPLE (CMakeLists.txt:31).
- Linux semantic drift in the seam refactor: `configureLayerShell` moved verbatim to platform_linux.cpp:215-238 (anchors, layer, scope, activate-on-show all identical); `xdg-mime` default-handler query moved verbatim into `LinuxPlatform::defaultHandlerState` (lines 186-203); `setAutostart`/`autostartEnabled` now route through the platform seam with unchanged behavior; `registerActivation` delegates to `Lane::registerActivation` unchanged; `requestActivationToken` keeps the resolved-once + 300 ms fallback contract. The only unconditional Linux-visible behavior change found is finding 7 (`maybeFirstRunSettings` in `launch()`), plus the narrowed socket-path bound in finding 5.
- `blockedChain` refactor (src/core/launcher.cpp:103-141): Linux path is a literal extraction (`isBlockedInterpreterChain` now calls `blockedChain(path, false)`); the macOS additions (`.app`/dir rejection, `open`/`osascript`/`swift`/`script`/`tclsh`/`wish`/`shortcuts`/`lldb`/`automator`) apply only under `macRules`. `macFixedOpenArgs` ignores `target.exec`/`target.args` entirely (verified by test_launch_mac's hostile-exec case), and `action:email` encodes the whole URL into `mailto:?body=` so query parameters cannot inject `to`/`cc`/`subject` (test pins the no-unencoded-`&`/`=`/`?` invariant).
- `.app` bundle scanning (src/core/discovery.cpp:1333-1420): requires http/https in `CFBundleURLTypes`, rejects empty/slash/dot-dot `CFBundleExecutable`, requires the exec to canonicalize inside `Contents/MacOS` (symlink-escape fixture exists and is tested), dedupes by bundle id (shorter path wins) and canonical path, skips Lane itself, and is a no-op on Linux because `bundleDirs` is empty there (`defaultDiscoveryPaths` sets it only under `Q_OS_MACOS`). `QDir::Hidden` correctly catches chflags-hidden system apps like Safari. `g_macBundlePaths` is populated only from `scanMacBundles` on the GUI thread; single-threaded use verified (discovery runs in `reload()`/`rediscover()`).
- Profile-root table refactor (discovery.cpp:578-640): rule order preserves the old if-chain order exactly (zen before firefox, brave-beta needles before plain brave, chrome before chromium); linux candidate lists are char-for-char the old literals; `macBrand` applies only when `applicationSupport` is set, so Linux fingerprints cannot change. test_profileroots pins this.
- Tests have real assertions: test_urlevents asserts drain order, the 8-cap, drop count, scheme filter, and post-sink dispatch; test_notifymap pins one-shot take, unknown-key false, capacity bound, and LRU eviction order; test_launch_mac asserts exact argv for the email/Safari fixed routes, header-injection impossibility, and that hostile exec/args are ignored; test_discovery_mac exercises the fixtures including hidden, binary-plist (explicit skip off-macOS), missing-exec, and symlink-escape cases. No tautologies found.
- Signed bundle pipeline (packaging/mac/bundle.sh): install copies the unsigned bundle via ditto then signs in place (copying signed bundles breaks Mach-O seals, correctly diagnosed); `codesign --deep` re-binds the Info.plist slot; `xattr -rc` precedes signing; verify loops every Mach-O; the final `otool -L` sweep fails the script on any surviving /opt/homebrew or /usr/local reference. `LSUIElement`, `LSApplicationCategoryType`, `CFBundleExecutable`, and the deliberate no-`LSHandlerRank` on URL types are all present in the shipped plist (verified against the built bundle).
- ctest on the port machine: 20/20 pass on e73f28b, including test_singleinstance, test_urlevents, test_notifymap, test_discovery_mac, test_launch_mac, test_qml.

## Open questions

1. `setDefaultApplicationAtURL:toOpenContentType:public.url` re-pointed http/https scheme handlers on this machine (verified), but the `public.url` Viewer role still shows `com.operasoftware.opera` while `public.html` moved to Lane fully. Either the call's scope is narrower than the name implies, or `.webloc` opens are governed by a different role slot; the lopsided result deserves a design note since `.webloc` files are the one file-open Lane could actually serve.
2. Did the consent prompt the code expects actually appear for the content-type call, or did it take effect silently? If silent, `m_changeDeclined`'s "the user declined" interpretation is weakened further.
3. Is `com.apple.application-bundle -> app.lane.lane` in the secure plist a residue of earlier `toOpenContentType` experiments on this machine, or something the current calls still flip? If the latter, `makeDefaultHandler` is claiming roles far outside intent.
4. Task 9.3 (owner-attended key/menu/quit/first-run/login-item verification) is still open; findings 1 and 2 are the kind of thing it would surface.
