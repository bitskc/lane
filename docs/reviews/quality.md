# Lane code quality and test audit

Fixing commits: finding 1 and finding 2 are `bd6f588` (`linuxDefaultHandlerState`, `test_linux_handler`, `linkFilesUnwrapToTheirEmbeddedUrl`). Finding 3 and finding 4 are `25ac107` (`Controller::save`, `pickerVisibleChanged`, and the unreachable LRU branch are gone; `ensureEngine` drops the engine when the load has no root object).

Scope: `src/app/Controller.cpp` (1315 lines) and `Controller.h` (382), the 20 ctest targets in `tests/CMakeLists.txt`, and the error paths in `unshortenSync` and `forwardToPrimary`. Round-1 rows 9-19 in `docs/designs/gstack-full-analysis.md` are not repeated here.

## Verdict

**Do not split Controller.** It is a long QML facade, not a god object. Routing, discovery, launch guards, and config I/O already live in `src/core/`. What remains is session state (`m_click`, `m_config`, `m_targets`) plus three windows that all bind one context property named `controller`. A second type would still share that state.

The test suite matches the repo rule in `openspec/changes/native-macos-app/tasks.md` ("real tests only; no wiring or tautology tests") for the four named files: they check queue order, bounds, eviction, socket delivery, and launch argv. They are not echo tests. Two holes matter: Linux reports "partial" default-handler status whenever Lane is not the handler for every scheme, and the `.webloc` / `.url` unwrap added for the file-open fix has no test.

`git grep` for `TODO`, `FIXME`, and `HACK` in source is empty (the only `XXX` hit is the Firefox `[InstallXXXX]` comment in `src/core/discovery.cpp`).

## Considered and fine

- **Controller size.** About 240 lines are settings setters that assign one `Config` field, `persist()`, and emit `settingsChanged`. `openUrl` (554-629) is the session: capture the activation token, refuse re-entry, run `runPipeline` / `route`, `applyDecision`. Target edits (782-984) repeat `persist` + `applyConfigToTargets` + `setTargets` five times, with comments that say why remove/rename cannot just rescan. That wants a private helper, not a new type. Hold, picker, and settings engines share `m_click` and the target list; splitting them splits the object QML already treats as one.
- **Launcher guards.** `isBlockedInterpreterChain` and `isBlockedInterpreterChainMac` are one-line wrappers over `blockedChain` (`src/core/launcher.cpp:107-160`, 274-281). `osascript` is in both name sets on purpose (lines 88-90). Not a second copy of the walk.
- **`m_changeDeclined` initial `false`.** Not a dead arm. `platform_macos.mm:300-306` reports `Declined` only after `makeDefaultHandler` stored `!ok` on the accepted-but-not-us path (lines 360-364). Process start correctly shows `unknown` until that happens. The API-error path no longer sets the flag (round-1 fix). The flag stays true until a later attempt stores false, so an in-process switch to another browser still reads as declined; Overview also prints `currentHandler`, so the current owner is not hidden. Left as residual, not re-opened.
- **`DefaultBrowserWatcher` on macOS.** Not on the macOS path. `Controller.cpp:122-134` constructs the watcher only when `watchesDefaultHandlerByFile()` is true (Linux). The else branch polls `onMimeappsChanged` every 60 s. `src/CMakeLists.txt` compiles the watcher into the macOS binary and says so. `setWatchdogEnabled` (372-378) starts or stops whichever object exists.
- **Platform methods.** All 12 virtuals on `Platform` have a Linux body and a macOS body (`notificationsDenied` uses the header default on Linux and an override on macOS). Each has a call site in `Controller`, `main`, or the macOS notification path. `registerActivation` on macOS returns true without using the callbacks because delivery is `QFileOpenEvent`; that matches the header. Nothing was left behind as an empty stub after the seam move.
- **`unshortenSync` timeout does not leave `loop.exec` running.** `src/core/unshorten.cpp:31-38` connects both `QNetworkReply::finished` and a single-shot `QTimer` of `timeoutMs` to `QEventLoop::quit`, then `exec`s. Either event returns from `exec`. The transfer timeout on the request (line 27) is a second way for `finished` to fire. After return, a reply that is not finished fails open to the original URL (lines 40-61). `reply->deleteLater()` runs, then the stack `QNetworkAccessManager` destroys the reply (it parents `head()` replies), and the stack `QEventLoop` is destroyed on return, which drops the `finished` connection. Controller passes 1800 (`Controller.cpp:1226`) and will not enter this loop at all when unshorten is off. `m_inOpenUrl` (574-585) queues re-entrant `openUrl` calls from that nested loop, capped at 4, newest kept. `tests/test_unshorten.cpp` only covers the two gates that return before any socket (`isShortener`, `isSafeOpenUrl`) plus empty input, using a 50 ms budget to prove those returns are synchronous. The timeout and redirect arms are untested; the source does not hang.
- **`forwardToPrimary` on disconnect mid-frame fails closed.** A short `write`, a `waitForBytesWritten` failure, an empty ack, or any ack other than exactly `ok\n` returns `Failed` (`SingleInstance.cpp:105-140`). `claim()` treats `Failed` as fatal and does not `removeServer` (193-197, 217-221). On the primary, `readFrame` returns without an ack while the buffer has no newline (260); `disconnected` only `deleteLater`s the socket (279). A peer that dies mid-frame cannot be mistaken for `NoPrimary`, so this process will not unlink a live socket. The URL for that invocation is dropped on purpose (header comment, lines 50-53). `payloadSplitAcrossWritesIsDelivered` checks that a half frame is not parsed early; it then sends the rest. Nothing drops the client mid-frame. `fatal()` calls `std::_Exit`, so that arm cannot be asserted inside the test process without killing it.
- **The four named tests are behavior checks.**
  - `test_urlevents`: order, scheme filter, cap, immediate sink. Gap is finding 2, not a tautology.
  - `test_notifymap`: one-shot `take`, unknown keys, size stays at `kMaxEntries`, oldest key `act-0` is gone and the two newest keys remain. The `act-%` strings match `add()`'s identifier contract; the test does not reimplement eviction.
  - `test_singleinstance`: one primary under concurrency, inode stable across a forwarded claim, stale regular file reclaimed, token carried, split frame delivered, malformed payload acked `err` and not delivered, overlong macOS path returns empty. Ack asserts use `startsWith("ok")` / `startsWith("err")`, which is looser than the client's exact `ok\n` compare. Still a delivery check.
  - `test_launch_mac`: mailto body encoding and the `&to=` injection case, Safari `open -b` argv, exec/args ignored for fixed routes, Linux `open` still launches and the helper records the URL, non-web URLs refused, `open` / symlink / `.app` directory blocked on the mac chain only. `macOpenArgsRefuseEmptyUrl` uses `value_or({"x"})` compared to an empty list, so both `nullopt` and a non-empty argv fail.
- **QMenu and OverlayWatcher.** `new QMenu()` has no parent; `~Controller` clears the tray menu and deletes it (`Controller.cpp:137-146`). `OverlayWatcher` is parented to the `QWindow` (`platform_macos.mm:376`). `m_settingsEngine` is a child of the controller and is `delete`d in the destructor before members the QML engine binds.

## Open questions

- Finder `.webloc` files are often binary plists. `urlFromLinkFile` decodes the file as UTF-8 and runs a text regex (`UrlEventFilter.cpp:57-65`). A binary plist would miss and be ignored like any other local file. Not confirmed against a Finder-written sample.
- Round-1 notes said 21/21 ctest. This tree registers 20 `add_test` names: 14 `lane_test` bins, `test_pickermodel`, `test_watchdog`, and four behind `LANE_KDE_DESKTOP OR LANE_MAC_DESKTOP`. No 21st target in CMake.
- `requestQuit` and a build-level "exactly one platform backend" check are in the native-macos test plan and are not in `tests/`. `requestQuit` itself is a short, readable branch (766-779). The missing state-machine test is the one that would have caught finding 1.
