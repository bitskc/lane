## Should fix

### 2. `src/app/PickerModel.cpp:136-154` — sections not in `kSectionOrder` are dropped, not appended

`sectionFor()` today maps every `Kind` to one of the five `kSectionOrder` entries (including the `default` → `"Browsers"` fallback at `PickerModel.cpp:97-112`), so current targets are not lost.

The old first-encounter partition would still surface a **new** section name if `sectionFor()` ever returned something outside the list. The new loop only iterates `kSectionOrder` and never drains leftover `buckets` keys, so a future section would silently disappear from the picker.

**Recommended fix:** after the `kSectionOrder` loop, append any remaining buckets in stable key order (or document that `sectionFor()` and `kSectionOrder` must stay in lockstep).

### 3. `CHANGELOG.md:44-50` — `--list` kind column filed under `### Fixed`

Adding a fourth `kind` column to `lane --list` is new CLI surface for agents, not a bugfix. The entry fits `### Added` better and matches how AGENTS.md presents it (`lane --list # print targets: id, name, exec, kind`). Minor hygiene; not blocking once the conflict junk is gone.

---

## Advisory (acceptable as-is, noted for awareness)

### 4. `src/app/Controller.cpp:473` — `reload()` on the UI thread when Settings opens

`reload()` (`Controller.cpp:667-691`) synchronously rescans desktop entries and profile stores via `discoverTargets()`. That is the same work `rediscover()` already triggers from Settings. Opening Settings may hitch briefly on large installs; no re-entrancy loop (`openSettings` does not call itself) and `settingsChanged` + `m_targetModel->setTargets()` give QML the refresh it needs.

### 5. `src/app/main.cpp:124-129` — fourth `--list` column

`kindName()` (`types.h:159-174`) emits `browser`, `container`, `pwa`, `action`, `app`. AGENTS.md documents the fourth column consistently (`AGENTS.md:158`, `214`). No in-repo parsers of `lane --list` output found; tab-separated fourth field is backward-compatible for scripts that only read the first three columns. **No break identified.**
