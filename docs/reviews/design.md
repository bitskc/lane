# Design/UX review — macOS port + cross-platform picker/Settings UX

Reviewer: DesignReview-2. Scope: `src/qml/{Picker,Settings,Hold}.qml`, `src/qml/pages/*`, `src/qml/ui/*` plus the Controller/platform code behind them. All claims verified against source or probed live on the MacBook (Qt 6.11.2, macOS 26.6.1) with read-only `qmltestrunner`/`qmlscene`/compiled probes; synthetic offscreen runs marked.

## Verdict

Ship after fixes: the interaction model is sound, but macOS silently swallows `.html` files Lane may own, the "declined" copy misreports system errors, a third of the icon set renders blank, the "declined"/banner state never signals QML, and the LaneIcon `sourceSize` self-binding behind the observed RangeError should be replaced with a fixed physical size.

## Considered and fine

- **⌥-letter shortcut delivery with focused TextField**: verified on the MacBook via `qmltestrunner` — `Alt+A/P/E/S/R` all activate their `Shortcut` while a `TextField` holds focus, and insert no text (Qt6 `ShortcutOverride` declines non-plain modifier letters). Dead-key corner (⌥E is a dead key on US layouts) can only be falsified by real hardware typing — stays in 9.3. `Keys.onPressed` intercept covers the keys TextField does claim (digits, `,`, `.`, ⌘C) and the digit/`,.` paths are modifier-gated so `!`/`@` still type.
- **`pick(row)` bounds**: `targetAt` returns an empty target out of range → early return, no crash (Controller.cpp:629-636).
- **First-run Settings on bare launch**: correct — main.cpp:196 gates on empty positional args and not `--daemon`/`--settings`; `open -a` passes no args. `--settings` alone does NOT consume `m_firstRun`, so the next bare launch still opens Settings once — reasonable.
- **Empty states**: filtering shows "No matching destinations" + "esc clear" (accurate — Esc clears text first); zero targets shows recovery shortcuts. Both render in the same column, no overlap.
- **Esc two-step** (clear filter then cancel) matches the empty-state hint copy.
- **Autostart messaging**: `SMAppServiceStatusRequiresApproval`/`NotRegistered`/`NotFound` map to real error strings surfaced as the toggle description — honest failure reporting.
- **`requestQuit` two-step** (cancel pending pick/hold, then quit) is implemented per D2 and reachable from the status item Quit.
- **`onActiveChanged` focus-loss cancel** is correctly mac-gated and flag-gated; Hold window does not use it (Hold cancels via its own dim click or Esc/Space — consistent).
- **Pointer-screen placement** (`screenAt(QCursor::pos())` before show, Controller.cpp:1070-1073) plus `onVisibleChanged` re-size means the overlay covers whichever display the click came from.
- **`accessibleRole`/names** on picker card, list items, filter field, footer actions are all present and platform-worded (Command/Option in Accessible.descriptions).
- **Zero-target Alt+S/Alt+R shortcuts** are correctly `enabled: list.count === 0 && targetCount === 0`, so they cannot fire over a populated list.
- **Settings window raise** calls `requestActivate()` + `raise()` (Controller.cpp:744-746); whether `QWindow::requestActivate` fronts an LSUIElement app on macOS 26 needs the device pass — flagged as open question, not a finding.
- **Denied notification drop path**: honest — logs a warning, sets the flag, drops the toast (platform_macos.mm:206-210). No fake success.
- **`handlerForScheme` identity check** (sameId AND resolved real path, platform_macos.mm:67) correctly distinguishes "another Lane copy" from this install → `other-copy` state with accurate Overview copy.
- **Dim-opacity/`reduceMotion` gating** reads `accessibilityDisplayShouldReduceMotion` live with a macOS 14 `available` guard matching the 13.0 deployment floor.

## Open questions

1. Does the picker actually appear over a full-screen Space on macOS 26 (task 6.2, still unchecked)? The `MoveToActiveSpace`-only collection behavior predicts failure, but only device proof settles whether `WindowStaysOnTopHint`'s level compensates.
2. Does `requestActivate()` on an LSUIElement app bring Settings frontmost when opened from the status item or on first run, or does it stay behind the frontmost app (making first-run onboarding invisible)?
3. Which wins for ⌘Q: the hidden app-menu Quit item (`quit:` → immediate terminate, bypassing `requestQuit`'s cancel-first) or the QML `Shortcut`? Determines whether quitting mid-pick silently drops the URL.
4. What is the exact trigger for the LaneIcon RangeError? The `sourceSize→implicitSize→width→sourceSize` cycle is real, but no standalone repro fired it — knowing the trigger (delegate incubation under Retina window attach?) decides the minimal fix.
5. Do ⌥E/⌥A typed on real hardware into the focused filter field still fire their shortcuts when the key is a dead key (US layout) — the case synthetic `keyClick` cannot reach?
6. Should `file://` URLs routed to Lane via `public.html`/`public.url` ownership open the file in a browser, or should Lane not own those content types at all? (Spec-level: CFBundleDocumentTypes was added only for default-browser list eligibility; the `public.html` `setDefaultApplicationAtURL` call is the one that can actually win the role.)
