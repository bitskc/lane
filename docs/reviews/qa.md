# QA / bugcheck review — Lane (native macOS port round)

Verified 2026-10-17 against HEAD e73f28b on cachy (Linux) and andys-macbook-pro (macOS 26.6.1, build-mac).

## Verdict

SHIP with reservations. Both test suites fully green (Linux 21/21, macOS 20/20), CLI and single-instance forwarding verified live on both OSes, malformed URLs handled cleanly. Findings are polish-level: one doc/limit contradiction, one misleading first-run edge case, leftover argv on the macOS email target, and several stderr-noise lines.

## Test results (observed)

- Linux: `QT_QPA_PLATFORM=offscreen XDG_RUNTIME_DIR=/tmp/grab-run ctest --test-dir build --output-on-failure` → 21/21 PASS (15.1s). The task brief expected 16; the suite has grown to 21 targets — no drift, all green.
- macOS: `ctest --test-dir build-mac --output-on-failure` on the MacBook → 20/20 PASS (19.1s). (test_qml count differs from Linux because of Linux-only targets.)
- `lane --list` macOS: 47 targets, exit 0. Linux: 42 targets, exit 0.
- `lane --explain https://example.com/?utm_source=x` macOS: correct pick decision, param stripped. `--explain javascript:alert(1)`: action=pick reason=blocked, no crash.
- Single-instance forwarding, Linux (private bus + XDG_RUNTIME_DIR): `lane <url>` and `lane --settings` against a `--daemon` primary both exit 0; primary received both (picker engine loaded).
- Single-instance forwarding, macOS: primary bound `$TMPDIR/lane-501.sock` (verified `srwx------`), `lane --rediscover` and `lane https://qa-forward-test.invalid/path` both forwarded and acked, exit 0; daemon processed them (duplicate-container reload warning + picker load in its log). Socket file removed on clean exit.
- Stale-socket path: an orphaned `lane-instance.sock` left by a killed offscreen daemon was correctly reclaimed by the next launch (probe → NoPrimary → rebind under lock). Linux D-Bus name collision from a second XDG_RUNTIME_DIR instance exits 1 with a clear message — correct behavior, though it leaves the fresh socket bound for ~0s before exit.
- LS registration on the Mac: bundle claims `com.apple.default-app.web-browser`, `public.url`, `public.html`; URL types carry no LSHandlerRank (as designed); category `public.app-category.utilities` present. Verified via `lsregister -dump` and `plutil -p`.
- Note: the installed /Applications/Lane.app predates commit 9541fa8 and still listens on the old Qt-named socket (`$TMPDIR/.qpkvat/s`); new builds use `lane-<uid>.sock`. Upgrade across that change means the old daemon and new CLI can't see each other until the old daemon restarts — one-time migration wrinkle, not a bug in this tree.

## Considered and fine

- `forwardToPrimary` protocol (SingleInstance.cpp:75-142): bounded payload (64KiB), read-first-then-wait ack loop avoids the self-block the comment describes, `err`/`ok` acks verified, write-short and flush-failure both treated as Failed → fatal rather than silent drop. Probe-before-bind + claim-lock + re-probe ordering closes the unlink-a-live-primary race; claimLock released only after connect, never held during delivery.
- ENOTSOCK/stale-regular-file reclaim on macOS narrows to `stat() && !S_ISSOCK` (SingleInstance.cpp:88-90) — cannot unlink a live listener.
- handleNewConnection (SingleInstance.cpp:239-288): per-client shared state, 10s idle abort, ack-before-dispatch (socket never touched after onMessage's nested loop), deleteLater on disconnect/error — no double-delivery or drop path found; verified end-to-end on both OSes.
- UrlEventFilter queueing: FileOpen events before sink exist queue FIFO (capped 8), drain in order once setSink runs in main.cpp:187 after argv handling so an explicit URL wins first — matches the comment. file:/mailto: dropped with a warning; test_urlevents covers order, bound, scheme filter, live dispatch.
- No macOS double-delivery path found: LaunchServices never passes the URL in argv, so the argv path and the FileOpen path cannot both fire for one click [INFERENCE for `open -a` semantics: `open` delivers a reopen event, not argv, to a running app; argv `--args` only reaches a cold start]. Both forward paths funnel into the same `onMessage`/`openUrl` with the m_inOpenUrl re-entrancy guard.
- unshortenSync + pipeline (unshorten.cpp, pipeline.cpp:153-170): single-hop manual redirect, 1.8s cap, HEAD only, redirect target re-validated through isSafeOpenUrl + private-host check (raw `Location` header fallback rejects NULs and >4096), hop count 4 with visited-set loop detection — malformed input (`javascript:`, empty, 8KB+, userinfo, embedded newlines) all lands in the blocked/isSafeOpenUrl path, verified by `--explain` runs above. No crash surface found.
- launchTarget (launcher.cpp:373-459): sanitizes URL, resolveExecutable + symlink-chain blocklist (mac additions incl. `open`/`osascript`/`.app`/dirs, fail-closed on missing hops, 40-hop cap), macFixedOpenArgs bypasses the blocklist only for fixed `/usr/bin/open` routes built from kind+bundleId (never target.exec), mailto body fully percent-encoded, XDG_ACTIVATION_TOKEN set/restore window is single-thread-safe and restores prior state.
- flatpak argv gate (launcher.cpp:180-239): only --command values are basename-checked; subcommand must literally be `run` and a dotted app id required — `flatpak run --command=sh` blocked, `flatpak --command=sh run app.id` blocked.
- CrashLog (CrashLog.cpp): async-signal-safe handler uses only open(O_EXCL|O_NOFOLLOW)/clock_gettime/getpid/write/close on an altstack; g_writing prevents double-entry on abort-after-terminate; ring snapshot re-checks sequence after copy. QtFatalMsg abort still produces one log.
- UpdateChecker: ManualRedirectPolicy, own redirect vetting (isSafeUpdateRedirect, ≤3 hops), 8s transfer timeout, stale-reply guard via m_reply identity, Manual cookie control + null jar. Verified via test_updatechecker + code read.
- platform_macos notify(): authorization refresh → denied flag → request-once flow all lands on main queue; missing-action tap logs instead of crashing; body tap correctly does not run the action (platform_macos.mm:160-167).
- makeDefaultHandler: chained public.url → public.html setDefaultApplicationAtURL calls, error paths finish(false) on main queue, success claimed only after re-querying both schemes (platform_macos.mm:304-362). Consistent with the known macOS 26 permErr workaround.
- bundle.sh: deploys before signing, rewrites Homebrew LC_ID_DYLIBs, strips signatures before re-signing, verifies every Mach-O + bundle at both locations, otool prefix gate, quarantine strip on both copies. Only nit: the post-sign otool check (:119-127) scans the build-tree bundle but not the installed copy — same content, same risk either way.
- `openUrl` re-entrancy: m_inOpenUrl queue bounded at 4 (newest kept), pending activation tokens captured per-call and restored on drain — verified by trace; the env-token capture happens before the guard so nested calls cannot inherit the outer token.
- QML Shortcut warning at Picker.qml:50 is noise only — Qt binds the first of the several StandardKey.Quit sequences (⌘Q on macOS).
