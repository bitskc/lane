## Problem Statement

Lane v0.3.0 is a technically superior Wayland link router: resident Qt6/Kirigami daemon, <20ms layer-shell overlay, path-scoped memory (`Alt+A` / `,` / `.`), hold HUD, and native container/PWA discovery. However, compared to top-tier commercial macOS tools (Velja, Choosy) and power-user expectations on Linux, Lane still has five critical capability, UX, and distribution seams:

1. **Dirty Tracking URLs**: Users clicking links from Slack, Twitter/X, emails, and newsletters get tracking junk (`utm_*`, `fbclid`, `gclid`, `si`). Velja provides automated removal out of the box; Lane currently requires users to hand-write regex substitutions in JSON.
2. **Context Blindness across KDE Activities**: Plasma users separate contexts via Activities (Work, Personal, Research). Today Lane uses global rules; switching default browser per Activity currently requires manual re-selection.
3. **Silent Default-Browser Hijacking**: Upgrades of Firefox, Chrome, or Zen silently re-claim `x-scheme-handler/http` in `mimeapps.list`. Lane currently only notices if the user opens the Settings Overview page.
4. **Friction in Opening Disposable/Private Windows**: Users clicking an untrusted or one-off link often want a private/incognito window immediately. Currently, private profiles are hidden from the picker (to prevent clutter), forcing users to create an explicit rule or copy the URL.
5. **Empty-Picker Dead Ends & Visual Gaps**: When a filter typo produces zero matches, the picker gives no escape path except `Esc`; first-run zero-browser detection has no setup CTA; README screenshots show obsolete 0.1-era Tern branding.

---

## What Makes This Cool

- **Unstoppable Privacy Default**: Clean Links removes invasive surveillance parameters transparently before any browser sees them, with zero network lag and zero external dependency.
- **Activity Context Switching**: Lane becomes the *only* tool across any desktop platform that natively switches default browser personas based on your desktop environment's current workspace activity.
- **One-Key Private Flick (`Alt+P`)**: Pressing `Alt+P` on any link instantly diverts that URL into the selected browser's isolated private window without manual profile switching.
- **Defensive Watchdog**: Lane guards its own default-browser registration and offers a 1-click restore notification when another browser steals it.

## Diagnostic Answers (Phase 2A)

### Q1: Demand Reality
- **Velja's #1 praised feature** in public reviews is built-in tracking parameter removal ("Clean Links").
- **KDE Community Stated Demand**: On Linux, Junction issue #9 requested container/profile routing, but Junction refused to build it. Velja users resort to complex macOS Shortcuts + Focus Filters to achieve Activity-style routing. Lane can do it natively with zero external dependencies.

### Q2: Status Quo
- **Tracking params**: Users either install browser extensions (ClearURLs) which only work *after* the browser opens, or live with bloated URLs.
- **Work vs Personal Activities**: Users manually copy-paste links or open links in the wrong browser, then copy them over.
- **Hijacked default browser**: User clicks a link in Discord, suddenly a fresh Firefox profile opens instead of Zen/Lane. User wonders why Lane "stopped working".

### Q3: Target User & Narrowest Wedge
- **Target User**: Power Linux user (KDE Plasma on Arch/Cachy/Garuda/openSUSE/Fedora) managing multiple browser personas (Work Google account, Personal Zen, Client Firefox Container, PWA tools).
- **Narrowest Wedge**: A single "Clean Links" checkbox in Preferences, an `Alt+P` shortcut in the picker, and Activity matching in rules.

### Q4: Observation & Surprises
- Prior gstack review noted that users who enabled the hold bar loved the ability to cancel an accidental link open, but felt frustrated that opening in incognito still required copy-pasting the link.

### Q5: Future-Fit
- Linux desktops are standardizing on Wayland layer-shell and portal protocols. Electron-based choosers (Browserosaurus) are dying or dead due to cold-start resource bloat. A lean C++ Qt6 resident daemon is permanent infrastructure.

## Premises

| Premise | Status | Evidence / Falsification |
|---|---|---|
| Tracking param stripping can be done without breaking legitimate websites | **PARTIALLY VALIDATED** | Well-known parameters (`utm_*`, `fbclid`, `gclid`, `mc_eid`, `twclid`, `si`, `igshid`, `msclkid`) are safe to strip. Arbitrary parameter stripping breaks OAuth (`state`, `code`) and query-based routing (`id=123`). Scope must be limited to an allowlist of pure tracking keys. |
| KActivities is available on all Plasma installations | **VALIDATED** | `kf6-kactivities` (or `kactivities6`) is part of KDE Frameworks Tier 3 and is a core dependency of Plasma Workspace. |
| Detecting default browser status periodically is cheap | **VALIDATED** | `detectDefaultBrowserStatus()` parses `~/.config/mimeapps.list` directly; it does not need to spawn `xdg-settings` process repeatedly. |
| Private window launch arguments are standard across browser families | **VALIDATED** | Gecko uses `--private-window <url>`, Chromium uses `--incognito <url>`. Both already exist in Lane's `Target` structures for discovered browsers. |

## Approaches Considered

### Pillar 1: Clean Links (Tracking Parameter Stripping)
- **Approach A (Regex Substitutions via Existing Engine)**: Bundle a list of regex rules into `config.substitutions`.
  - *Cons*: Regexes on full URLs are slow, fragile with query string order, and clumsy to toggle.
- **Approach B (Dedicated Query-Param Filter in `pipeline.cpp` — RECOMMENDED)**:
  - Add `bool stripTrackingParams = true` to `Config`.
  - In `pipeline.cpp:cleanTrackingParams(QUrl)`: parse query items via `QUrlQuery`, filter against a `QSet<QStringView>` of known tracking keys (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `fbclid`, `gclid`, `gbraid`, `wbraid`, `msclkid`, `twclid`, `mc_eid`, `si`, `igshid`), and reconstruct the URL.
  - Zero-marginal-cost, deterministic, runs in <10 microseconds, no regex compilation overhead.

### Pillar 2: Plasma Activity-Aware Routing
- **Approach A (D-Bus Call per Link)**: Call `org.kde.ActivityManager` over D-Bus when routing.
  - *Cons*: IPC latency on the critical link-click path.
- **Approach B (`KActivities::Consumer` Signal-Driven Cache — RECOMMENDED)**:
  - Add `KActivities::Consumer` to `Controller` or a dedicated `ActivityWatcher`.
  - Listen to `currentActivityChanged(QString)`. Maintain `QString m_currentActivityId` in memory.
  - Add `QString activityId` / `QString activityName` to `Rule` in `src/core/types.h`.
  - In `matcher.cpp`: if `rule.activity` is non-empty, match against `currentActivity`.
  - In `Config`: support optional `activityDefaults: QHash<QString, QString>` (mapping Activity ID → default target ID).

### Pillar 3: Default Browser Watchdog
- **Approach A (Continuous Inotify on `mimeapps.list`)**: Watch the file via `QFileSystemWatcher`.
  - *Cons*: Every file touch triggers checks; noise during package upgrades.
  - *Pros*: Instant alert.
- **Approach B (Event-Driven Watchdog with Debounced Notification — RECOMMENDED)**:
  - Watch `~/.config/mimeapps.list` via `QFileSystemWatcher`.
  - Check `isLaneDefaultBrowser()` on daemon start, on file change (debounced 2s), and on `openSettings()`.
  - If status changes from `true` to `false`, fire a KNotification:
    - Title: `"Default Browser Changed"`
    - Text: `"%1 is now your default browser. Click to restore Lane."`
    - Action Button: `"Restore Lane"` (invokes `setDefaultBrowser()`).

### Pillar 4: Dedicated "Open in Private Window" (`Alt+P`)
- **Approach A (Picker Hotkey `Alt+P` — RECOMMENDED)**:
  - When the picker overlay is open, pressing `Alt+P` takes the currently highlighted/suggested target:
    - If target has a paired private profile (e.g. `zen-private` for `zen`, `brave-incognito` for `brave`), launch that target immediately with the current URL.
    - If no paired target exists, append the engine's private flag (`--private-window` or `--incognito`).
  - Add visual indicator in picker footer: `"Alt+P Private"`.

### Pillar 5: Empty Picker Recovery & Polish
- **Approach A**:
  - In `src/qml/Picker.qml`: if `pickerModel.count == 0`:
    - Case 1: `filterText` is non-empty: Show `"No matches for '%1' — Press Esc to clear"`. Pressing Backspace or Esc clears filter.
    - Case 2: `filterText` is empty: Show `"No browsers discovered — Press Alt+S for Settings or Alt+R to Rediscover"`.
  - Add keyboard shortcuts `Alt+S` (open settings) and `Alt+R` (rediscover) in Picker.

## Open Questions & Risks

1. **KActivities Dependency Scope**:
   - *Risk*: Does building against `KF6::Activities` prevent Lane from running on pure GNOME / Sway / Hyprland systems?
   - *Mitigation*: Wrap Activity integration in a clean abstract interface `ActivityProvider` or compile conditionally: `find_package(KF6Activities)`. If absent, activity matching cleanly degrades to no-op.
2. **Clean Links Edge Cases**:
   - *Risk*: Does removing `si` from YouTube links break anything?
   - *Evidence*: `si` is YouTube's internal sharing tracker. `youtu.be/xyz?si=123` works identically as `youtu.be/xyz`.
3. **Notification Spam**:
   - *Risk*: User deliberately changes their default browser and gets annoyed by Lane's notification.
   - *Mitigation*: Provide `"Don't show again"` action on the notification, persisting `watchdogEnabled: false` in `config.json`.

## Success Criteria

1. **Clean Links**: URLs with tracking parameters have those parameters stripped before routing when enabled in Preferences; OAuth/internal query parameters remain intact.
2. **Activity Routing**: When switching KDE Plasma Activity to "Work", URLs without explicit rules open in the Work browser default; when switching to "Personal", they open in Zen.
3. **Watchdog**: When another application modifies `mimeapps.list` to take over `x-scheme-handler/http`, Lane displays a desktop notification within 5 seconds offering a 1-click restore.
4. **Alt+P**: Pressing `Alt+P` in the picker opens the active link in a private/incognito window of the selected target.
5. **No Regressions**: Full CTest suite passes offscreen; zero impact on layer-shell overlay startup latency (<20ms).
